## Why This Matters

Every backend API eventually needs to persist data. An in-memory array works for learning, but it loses all data when the server restarts and cannot be shared across multiple server instances.

A database solves this. MongoDB specifically suits Node.js APIs well because:
- Documents are JSON-like (JavaScript objects)
- Schema-less by default (flexible for fast iteration)
- Easy to get started without complex setup

This chapter makes your in-memory data permanent.

## Core Concepts

### 1. What is a Database?

A database is a system that:
- Stores data **persistently** (survives restarts)
- Allows **querying** data (find, filter, sort)
- Ensures **consistency** (partial writes don't corrupt data)
- Supports **concurrent access** (many users at once)

```
WITHOUT DATABASE:

Server start -> users = []
GET /users   -> returns []
POST /users  -> users = [Alice]
GET /users   -> returns [Alice]

Server restart ->
GET /users   -> returns []  <- Alice is gone!

WITH DATABASE:

Server start  -> connects to MongoDB
POST /users   -> saves Alice to MongoDB
Server restart ->
GET /users    -> queries MongoDB -> returns [Alice]  <- Alice persists!
```

### 2. SQL vs NoSQL vs MongoDB

Two major categories of databases:

```
SQL (Relational):              NoSQL (Non-relational):
  PostgreSQL, MySQL              MongoDB, Redis, Cassandra

Stores data in TABLES          Stores data in DOCUMENTS (JSON-like)
Fixed schema (columns)         Flexible schema
Relations (foreign keys)       Embed or reference
JOINS across tables            Nested documents or lookup
Mature, strict consistency     Various consistency models
```

**MongoDB is a document database:**
- Data is stored as **documents** (JSON objects)
- Documents are grouped into **collections**
- Collections live inside a **database**

```
MongoDB hierarchy:

MongoDB Server
  |
  +-- Database: myapp
       |
       +-- Collection: users
       |    +-- Document: { _id: ..., name: "Alice", email: "alice@..." }
       |    +-- Document: { _id: ..., name: "Bob",   email: "bob@..."   }
       |
       +-- Collection: posts
            +-- Document: { _id: ..., title: "Hello", author: "Alice" }
```

SQL analogy:
```
MongoDB           SQL
----------        ----------
Database    <-->  Database
Collection  <-->  Table
Document    <-->  Row
Field       <-->  Column
```

### 3. The _id Field

Every MongoDB document automatically gets an `_id` field if you don't provide one.

It is of type **ObjectId** — a 12-byte identifier that:
- Is globally unique
- Embeds a timestamp
- Is generated by the driver (not the database)

```
ObjectId: 64a7f1b2c3d4e5f6a7b8c9d0

Breaking it down:
  64a7f1b2  <- Unix timestamp (seconds)
  c3d4e5    <- Machine ID
  f6a7      <- Process ID
  b8c9d0    <- Random counter
```

In Mongoose, `_id` is converted to a string when you call `.toJSON()` or send it in a response. You'll see it as `"_id": "64a7f1b2c3d4e5f6a7b8c9d0"` in your API responses.

### 4. Mongoose

Mongoose is an **Object Document Mapper (ODM)** for MongoDB and Node.js.

It adds on top of the MongoDB driver:
- **Schemas** — define the shape of your documents
- **Models** — classes for working with a collection
- **Validation** — built-in and custom validators
- **Middleware** (pre/post hooks) — run logic before/after operations
- **Query helpers** — chainable, expressive queries

Mental model: **Mongoose is to MongoDB what a TypeScript interface + ORM is to a SQL database. It gives structure to something structureless.**

Install:
```bash
npm install mongoose
```

### 5. Connecting to MongoDB

```javascript
const mongoose = require('mongoose');

async function connectDB() {
  try {
    await mongoose.connect(process.env.MONGODB_URI);
    console.log('MongoDB connected');
  } catch (err) {
    console.error('MongoDB connection failed:', err.message);
    process.exit(1);  // exit if we can't connect
  }
}

module.exports = connectDB;
```

In your `index.js`:
```javascript
const connectDB = require('./config/db');
const app = require('./app');

connectDB().then(() => {
  app.listen(3000, () => {
    console.log('Server running on http://localhost:3000');
  });
});
```

Your `.env` file:
```
MONGODB_URI=mongodb://localhost:27017/myapp
# or MongoDB Atlas cloud:
# MONGODB_URI=mongodb+srv://user:password@cluster.mongodb.net/myapp
```

Connection flow:
```
index.js
  |
  v
connectDB()
  |
  v  (success)
MongoDB connected
  |
  v
app.listen(3000)
  |
  v
Server is ready
```

### 6. Defining a Schema

A schema defines the structure of documents in a collection.

```javascript
const mongoose = require('mongoose');

const userSchema = new mongoose.Schema(
  {
    name: {
      type: String,
      required: [true, 'Name is required'],
      trim: true,
      minlength: [2, 'Name must be at least 2 characters'],
      maxlength: [50, 'Name cannot exceed 50 characters'],
    },
    email: {
      type: String,
      required: [true, 'Email is required'],
      unique: true,
      lowercase: true,
      trim: true,
      match: [/^[^\s@]+@[^\s@]+\.[^\s@]+$/, 'Invalid email format'],
    },
    password: {
      type: String,
      required: [true, 'Password is required'],
      minlength: [8, 'Password must be at least 8 characters'],
      select: false,  // never returned in queries by default
    },
    role: {
      type: String,
      enum: ['user', 'admin', 'moderator'],
      default: 'user',
    },
    isActive: {
      type: Boolean,
      default: true,
    },
    createdAt: {
      type: Date,
      default: Date.now,
    },
  },
  {
    timestamps: true,    // auto adds createdAt and updatedAt
    versionKey: false,   // removes __v field from documents
  }
);
```

**Schema types available:**

| Type | Example |
|------|---------|
| `String` | `'Alice'` |
| `Number` | `42`, `3.14` |
| `Boolean` | `true`, `false` |
| `Date` | `new Date()` |
| `Buffer` | Binary data |
| `ObjectId` | Reference to another document |
| `Array` | `[1, 2, 3]` or `[{...}, {...}]` |
| `Mixed` | Any type |
| `Map` | Key-value map |

---

### 7. Creating a Model

A model is a class created from a schema. It represents a collection and gives you methods to interact with it.

```javascript
const User = mongoose.model('User', userSchema);
// 'User' -> collection will be named 'users' (lowercase, plural)

module.exports = User;
```

```
Schema       -> describes the shape
Model        -> gives you the API to work with the collection
Document     -> an instance of a model (one record)

const User = mongoose.model('User', userSchema);
                                     ^
                                     Schema

const user = new User({ name: 'Alice', ... });
              ^
              Document (Model instance)
```

### 8. CRUD Operations with Mongoose

#### Create

```javascript
// Method 1: Model.create() - preferred
const user = await User.create({
  name: 'Alice',
  email: 'alice@example.com',
  password: hashedPassword,
});

// Method 2: new Model() then .save()
const user = new User({
  name: 'Alice',
  email: 'alice@example.com',
  password: hashedPassword,
});
await user.save();

// Both throw a ValidationError if schema validation fails
// Both throw a MongoServerError with code 11000 for duplicate unique fields
```

#### Read

```javascript
// Find all documents in the collection
const users = await User.find();

// Find with filter
const admins = await User.find({ role: 'admin' });

// Find with multiple conditions (AND)
const activeAdmins = await User.find({ role: 'admin', isActive: true });

// Find one document
const user = await User.findOne({ email: 'alice@example.com' });
// returns null if not found

// Find by ID (most common)
const user = await User.findById('64a7f1b2c3d4e5f6a7b8c9d0');
// returns null if not found

// Select specific fields (projection)
const users = await User.find().select('name email');  // only these fields
const users = await User.find().select('-password');   // exclude password

// Sort, skip, limit (pagination)
const users = await User.find()
  .sort({ createdAt: -1 })    // -1 = descending, 1 = ascending
  .skip(20)                   // skip first 20
  .limit(10);                 // return next 10

// Count
const count = await User.countDocuments({ role: 'admin' });
```

#### Update

```javascript
// Find by ID and update, returns updated document
const user = await User.findByIdAndUpdate(
  '64a7f1b2c3d4e5f6a7b8c9d0',
  { name: 'Alice Updated' },
  {
    new: true,        // return the updated doc (not the old one)
    runValidators: true  // run schema validators on update
  }
);
// returns null if not found

// Update using MongoDB operators
const user = await User.findByIdAndUpdate(
  id,
  { $set: { name: 'Alice' }, $push: { tags: 'javascript' } },
  { new: true }
);

// Update many
const result = await User.updateMany(
  { role: 'user' },     // filter
  { isActive: false }   // update
);
// result.modifiedCount = number of modified docs
```

**Important MongoDB update operators:**

| Operator | Action | Example |
|----------|--------|---------|
| `$set` | Set a field value | `{ $set: { name: 'Bob' } }` |
| `$unset` | Remove a field | `{ $unset: { tempField: '' } }` |
| `$inc` | Increment a number | `{ $inc: { views: 1 } }` |
| `$push` | Add to an array | `{ $push: { tags: 'js' } }` |
| `$pull` | Remove from array | `{ $pull: { tags: 'js' } }` |

#### Delete

```javascript
// Find by ID and delete
const user = await User.findByIdAndDelete('64a7f1b2c3d4e5f6a7b8c9d0');
// returns the deleted document, or null if not found

// Delete many
const result = await User.deleteMany({ isActive: false });
// result.deletedCount = number of deleted docs

// Delete one
await User.deleteOne({ email: 'alice@example.com' });
```

### 9. Schema Relationships

MongoDB doesn't enforce foreign keys. You handle relationships in two ways:

**Embedding** — store related data inside the document:
```javascript
const userSchema = new mongoose.Schema({
  name: String,
  address: {
    street: String,
    city: String,
    country: String,
  },
  // Array of embedded objects
  posts: [{
    title: String,
    content: String,
    createdAt: Date,
  }]
});
```

Good for: data that belongs together, read together, rarely changes independently.

**Referencing** — store an ID that points to another collection:
```javascript
const postSchema = new mongoose.Schema({
  title: String,
  content: String,
  author: {
    type: mongoose.Schema.Types.ObjectId,
    ref: 'User',   // references the User model
    required: true,
  }
});
```

Then use `populate()` to join:
```javascript
const posts = await Post.find()
  .populate('author', 'name email');  // load author's name and email
```

```
WITHOUT populate():
{
  "_id": "...",
  "title": "Hello World",
  "author": "64a7f1b2c3d4e5f6a7b8c9d0"  <- just the ID
}

WITH populate('author', 'name email'):
{
  "_id": "...",
  "title": "Hello World",
  "author": {
    "_id": "64a7f1b2c3d4e5f6a7b8c9d0",
    "name": "Alice",
    "email": "alice@example.com"
  }
}
```

### 10. Handling MongoDB Errors

```javascript
async function createUser(data) {
  try {
    const user = await User.create(data);
    return user;
  } catch (err) {
    // Duplicate key (unique constraint violation)
    if (err.code === 11000) {
      const field = Object.keys(err.keyPattern)[0];
      throw new AppError(`${field} already in use`, 409);
    }

    // Validation error
    if (err.name === 'ValidationError') {
      const messages = Object.values(err.errors).map(e => ({
        field: e.path,
        message: e.message,
      }));
      const error = new AppError('Validation failed', 400);
      error.details = messages;
      throw error;
    }

    // CastError: invalid ObjectId format
    if (err.name === 'CastError' && err.kind === 'ObjectId') {
      throw new AppError('Invalid ID format', 400);
    }

    throw err;  // unknown error, let global handler deal with it
  }
}
```

```
MONGODB ERROR TYPES:

MongoServerError (code 11000) -> Duplicate unique field
ValidationError               -> Schema validation failed
CastError                     -> Invalid field type (e.g., bad ObjectId)
MongoNetworkError             -> Can't connect to MongoDB
```

### 11. Complete Example: User Model and Service

**models/User.js:**
```javascript
const mongoose = require('mongoose');
const bcrypt = require('bcrypt');

const userSchema = new mongoose.Schema({
  name: {
    type: String,
    required: [true, 'Name is required'],
    trim: true,
  },
  email: {
    type: String,
    required: [true, 'Email is required'],
    unique: true,
    lowercase: true,
    trim: true,
  },
  password: {
    type: String,
    required: [true, 'Password is required'],
    minlength: 8,
    select: false,  // never included in queries unless explicitly requested
  },
  role: {
    type: String,
    enum: ['user', 'admin'],
    default: 'user',
  },
}, { timestamps: true, versionKey: false });

// Pre-save hook: hash password before saving
userSchema.pre('save', async function(next) {
  if (!this.isModified('password')) return next();
  this.password = await bcrypt.hash(this.password, 12);
  next();
});

// Instance method: check password
userSchema.methods.comparePassword = async function(candidatePassword) {
  return bcrypt.compare(candidatePassword, this.password);
};

module.exports = mongoose.model('User', userSchema);
```

**services/user.service.js (with MongoDB):**
```javascript
const User = require('../models/User');

async function findAll({ role, page = 1, limit = 10 }) {
  const filter = role ? { role } : {};
  const skip = (page - 1) * limit;

  const [users, total] = await Promise.all([
    User.find(filter).select('-password').skip(skip).limit(limit),
    User.countDocuments(filter),
  ]);

  return {
    data: users,
    pagination: { page: Number(page), limit: Number(limit), total },
  };
}

async function findById(id) {
  return User.findById(id).select('-password');
}

async function create(data) {
  const user = await User.create(data);
  const { password, ...safeUser } = user.toObject();
  return safeUser;
}

async function update(id, data) {
  return User.findByIdAndUpdate(id, data, { new: true, runValidators: true })
    .select('-password');
}

async function remove(id) {
  await User.findByIdAndDelete(id);
}

module.exports = { findAll, findById, create, update, remove };
```

## Mental Models Summary

| Concept | Mental Model |
|---------|-------------|
| MongoDB | A giant folder of JSON files, organized and queryable |
| Collection | A folder full of similar JSON files |
| Document | One JSON file (one record) |
| Schema | A template that defines what a document must look like |
| Model | The API to a collection — gives you create, find, update, delete |
| ObjectId | A unique fingerprint for every document, auto-generated |

## Common Mistakes

### Mistake 1: Not handling null from findById

```javascript
// BAD: crash if user not found
const user = await User.findById(id);
res.json(user.name);  // TypeError: Cannot read property 'name' of null

// GOOD:
const user = await User.findById(id);
if (!user) return res.status(404).json({ error: 'User not found' });
res.json(user);
```

### Mistake 2: Returning password in responses

```javascript
// BAD: password hash in response
const user = await User.findById(id);
res.json(user);  // includes password hash!

// GOOD: exclude it in query or schema
const user = await User.findById(id).select('-password');
// OR: use select: false in schema definition
```

### Mistake 3: Not using { new: true } in findByIdAndUpdate

```javascript
// BAD: returns the BEFORE document
const user = await User.findByIdAndUpdate(id, { name: 'Alice' });
// user.name is still the old name!

// GOOD: returns the AFTER document
const user = await User.findByIdAndUpdate(id, { name: 'Alice' }, { new: true });
```

### Mistake 4: Treating ObjectId as a string in queries

```javascript
// BAD: may fail for certain operations
const user = await User.findById('not-a-valid-objectid');
// throws CastError

// GOOD: validate before querying
const mongoose = require('mongoose');
if (!mongoose.Types.ObjectId.isValid(id)) {
  return res.status(400).json({ error: 'Invalid ID' });
}
const user = await User.findById(id);
```

### Mistake 5: Connecting to MongoDB in every file

```javascript
// BAD: connecting multiple times
// user.service.js
mongoose.connect(process.env.MONGODB_URI);

// post.service.js
mongoose.connect(process.env.MONGODB_URI);  // duplicate!

// GOOD: connect once in index.js/app startup
// All models share the same connection automatically
```

## Key Takeaways

- A **database** provides persistent, queryable, concurrent-safe storage
- MongoDB stores data as **documents** (JSON-like), grouped into **collections**, inside a **database**
- Every document gets a unique `_id` (ObjectId) automatically
- **Mongoose** adds schemas, models, validation, and middleware on top of the MongoDB driver
- Connect to MongoDB once at startup; all models share the connection
- **Schema** defines document shape; **Model** provides the API to query the collection
- CRUD: `Model.create()`, `Model.find()`, `Model.findById()`, `Model.findByIdAndUpdate()`, `Model.findByIdAndDelete()`
- Always use `select: false` for sensitive fields like passwords
- Always use `{ new: true }` in update operations to get the updated document back
- Handle three common MongoDB errors: duplicate key (11000), ValidationError, CastError
- **Embedding** = put related data inside the document; **Referencing** = store IDs and use `populate()`
